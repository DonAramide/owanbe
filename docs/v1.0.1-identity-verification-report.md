## Prerequisites (local dev)

1. **Postgres migrations** (Windows — no local `psql` required; uses Docker):

   ```powershell
   cd C:\dev\Owanbe
   .\scripts\apply-identity-migrations.ps1
   ```

   Or manually:

   ```powershell
   docker compose up -d postgres
   Get-Content infra\db\028_identity_v101.sql -Raw | docker exec -i owanbe-postgres psql -U postgres -d owanbe
   Get-Content infra\db\029_identity_dev_seed.sql -Raw | docker exec -i owanbe-postgres psql -U postgres -d owanbe
   ```

2. **Supabase auth seeds** (Dashboard → SQL Editor):
   ```text
   scripts/supabase/seed-dev-auth-users.sql
   ```

3. **API** — restart after build (`IdentityModule`):
   ```bash
   cd services/api && npm run build && npm run start:dev
   ```

4. **Mobile**
   ```bash
   cd mobile && flutter run -d chrome
   ```

## End-to-end journeys

### 1. Attendee — discovery then signup

| Step | Action | Expected |
|------|--------|----------|
| 1 | Landing → **I'm attending an event** | `/attending` |
| 2 | Enter `newguest@owanbe.dev` → Find invitation | Event summary (General Admission, dev event) |
| 3 | **Create account** | Signup with matching email |
| 4 | Complete registration | `POST /me/ticket-entitlements/link` runs; redirect `/attendee` |
| 5 | Dashboard | Ticket visible via `GET /me/ticket-entitlements` |

**No-match path:** Enter unknown email → “No event invitation found” + try again / browse events.

**Existing account:** `attendee@owanbe.dev` / `123456` → `/auth` or staff-less attendee sign-in → dashboard shows seeded VIP ticket.

### 2. Organizer

| Step | Route | Expected |
|------|-------|----------|
| Sign in | `/staff/login?role=organizer` | organizer@owanbe.dev |
| Onboarding (new signups) | `/organizer/onboarding` | 4-step wizard |
| Dashboard | `/home` | Organizer events load (200 on `/organizers/me/events`) |

**Sign up:** `/staff/signup?role=organizer` → verify email → onboarding wizard.

## Known limitations / production follow-ups

1. **Self-serve staff signup roles** — Supabase `app_metadata.roles` must be set via Auth Hook or admin API; dev seeds pre-assign roles.
2. **Phone verification** — UI collects phone; SMS OTP integration deferred (marked verified on submit in onboarding).
3. **Postgres user sync** — New Supabase signups need a user row in `users` (hook or provisioning job); dev uses SQL seeds.
4. **Vendor category** — Stored in onboarding UI state; persist to vendor metadata in a follow-up migration if required.
